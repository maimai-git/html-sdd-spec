# 状态与用户决策 Implementation Plan

> For agentic workers: 使用 executing-plans 在当前会话逐项实施，原审核会话做最终只读审核。

**Goal:** 页面准确显示当前工作状态，突出需要用户决定的事项。
**Architecture:** 复用事实源、快照与折叠入口，增加一个可选问题分类标记；模板与打包资产同步。
**Tech Stack:** Python 3.9+、标准库、原生 JavaScript、Node、Playwright CLI。
**Spec:** ../设计/状态与用户决策.md

## Global Constraints

中文文档与普通中文文案；单文件离线打开；无新运行依赖；固定排期枚举不变；兼容旧事实源；本次先本地交付，不推送。

## Review Focus

1. codingReady=false 可能已经在待验收阶段，不能回退为方案对齐中。
2. 未标记的问题保持待分类，不能推断没有人需要决策。
3. 已解决、已取消的问题不应出现在待处理列表。
4. 三项展示上限不能导致其他问题丢失，且问题文本必须转义。
5. 复合状态包含未完成或失败时不能染成完成色，排期原有颜色不变。
