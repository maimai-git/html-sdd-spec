# 目录筛选与紧凑布局 Implementation Plan

**Goal:** 将资产库已确认的通用交互直接实现到开源模型和模板，保持单文件离线、旧数据兼容。
**Architecture:** 一个可选开发状态字段、两类目录独立筛选、紧凑摘要弹层；无项目级补丁和新依赖。
**Tech Stack:** Python 3.9+ 标准库、原生 JavaScript/CSS、Node 与 Playwright。

## 已确认约定

- API/表的 developmentStatus 只能是已完成、部分完成、未开发，缺省待核实；status 保留范围/部署说明，不互相推断。
- 按状态与变更类型组合筛选，显示计数、分类独立保留、恢复全部；空结果清除详情和旧选中。
- 顶部分组、左目录右单项、整页排期不变，existingInterfaces 独立。
- 实例与 DDL 默认展开，仍能收起；只移除指定页面提示，校验仍保护敏感内容。
- 状态只放页头；版本、编码条件及需求问题用紧凑摘要入口，完整内容弹层不推高正文。
- 两行目录、长名称/path省略并悬停看全文，DOM保留完整文本供原生查找。
- configs 只列本阶段执行项，真实配置/SQL文件为执行源。模板不按标题或自由状态猜测、删改发布范围。

## 重点风险

错误类型不能使校验器崩溃；未知变更不能默认归为复用；空结果不能残留旧详情；跨分类筛选不能串状态；弹层不能被容器裁切；省略路径仍可被原生查找。既有未提交修改及本机索引缓存全部保留。
