# 状态与用户决策

用户已确认本次四项范围：状态真实、整体阻塞只展示一次、用户决策与技术核实分开、复合状态颜色准确。

## 方案

- 保留现有顶部分类、左目录右详情、排期整表。改造已有快照，保持单文件和离线打开。
- metadata.status 是当前工作状态；缺失时显示 readiness.overall，再缺失显示“状态待记录”。codingReady 只描述编码条件，不推断项目阶段。
- 整体编码条件只在顶部以一份折叠入口出现；子需求保留自身状态和验收。需要用户决定的内容仅在需求分类显示。
- questions 可选 requiresUserDecision：true 为用户决策，false 为 AI 核实，未填写为待分类。已解决或取消的问题不计为待处理。首屏最多三项用户决策，其余展开；技术核实和待分类保留可查看入口。旧数据不隐式变为“无需用户决定”。
- 使用现有状态色。复合文案中的阻塞/失败优先于未完成，待/未/部分优先于完成色。固定排期枚举不变。
- Agent 根据已有代码和业务依据分类问题；不新增必填字段或审批服务，不自动记录用户已确认。

## 取舍

采用已有快照与问题的局部改造，改动范围小且兼容现有事实源。新增仪表盘会增加密度，变更影响分析需要单独验证关联范围，留待后续。

## 验收

能够区分当前状态、未验证内容和需要人决定的事；全局条件只有一份；旧数据仍可打开且未分类显式保留；状态颜色一致；六类阅读与宽屏排期不回退。用标准库/Node 回归及 Playwright 检查真实生成页面，并截图。
