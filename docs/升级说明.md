# 目录交互升级

- 新版兼容旧事实源。API/表缺 developmentStatus 时显示待核实，不能按 status 文字补填；有证据时填写已完成、部分完成或未开发。
- changeType 沿用现有取值；API 可使用存量接口复用。筛选状态只在当前页面内按分类保留，不自动回写 JSON。
- 升级工具后，原项目生成脚本直接调用 check/render 即可；移除目录筛选 JS/CSS 注入和针对旧模板的字符串补丁，避免叠加两套筛选与布局。
- 只把本阶段实际要执行的配置/SQL列入 configs；source 可注明真实源文件，content 保留阅读快照。模板不会猜测发布范围或删除历史配置。
- 实例和DDL默认展开，用户仍可收起；版本、编码条件和问题通过摘要弹层阅读，支持Esc和外部点击关闭。

本轮是本地未发布版本。旧项目补丁和全局已安装工具尚未自动修改。交互示意见 examples/目录筛选/使用说明.md。

## 可重复浏览器回归

先生成示例，再用 Playwright CLI 打开 `examples/目录筛选/方案对齐.html` 的绝对 file URL，或预览服务中该页面的 URL。使用相同会话运行：

```bash
playwright-cli -s=sdd run-code --filename=tests/browser/catalog.js
```

脚本包含 78 项交互断言；从 file URL 打开时验证离线运行，截图写入 `output/playwright/catalog.png`。该工具仅用于开发验证，不是页面运行依赖。

排期可用状态筛选、优先级/序号排序和模块归类。建议为 plans.sequence 录入稳定唯一正整数，旧数据临时编号不会随筛选变化；归类模式在模块内排序，同模块同色。浏览器回归可用 `tests/browser/schedule.js`（18项检查），运行方式同上。
