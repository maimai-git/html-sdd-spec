# 从 v0.4.x 升级到 v0.5.0

通过 [安装指南](安装使用.md) 升级 CLI 和 Skill。进入业务仓库根目录，对已有需求目录执行以下命令。

```bash
html-sdd --version
cd html-sdd-spec/需求目录
html-sdd check 方案事实源.json
html-sdd summary 方案事实源.json
html-sdd render 方案事实源.json --output 方案对齐.html
```

保留原事实源和记录编号。用浏览器打开重新生成的 Vue 页面，在「剩余事项」对照 CLI 摘要。

| 旧记录 | 升级时怎么处理 |
| --- | --- |
| 整单标为可编码，但仍有子需求未确认 | 将 `metadata.readiness.codingReady` 改为 `false`，如实登记当前阻塞。所有未取消的子需求就绪后再改回 `true`。 |
| 已对齐的子需求缺记录 | 按校验提示补齐目标、范围、关联排期和验收例子。关联受影响的接口、表、架构与配置。整类确认不涉及时填写 `sectionCoverage` 和原因。 |
| 验收已通过，但证据仅有描述或缺失 | 关联实际通过的 `EVID-*` 记录。证据尚未核实的验收，保留待核实状态。开工前只需写清验收例子。 |
| 旧方案引用写在 `使用说明.md` | 将旧方案路径或共享链接、沿用说明和可定位的旧记录编号迁入 `metadata.previousSpecs`。专属操作步骤仍可留在使用说明。 |
| 生成脚本通过引用旧 `templates/` 或注入额外样式和脚本改造页面 | 改用 CLI 的 `render`。如需查阅模板源码，仓库内路径为 `html_sdd/assets/`。 |

`specVersion` 仍为 `0.1`。旧事实源可以读取。新版校验会指出声明已经可编码但缺少记录的部分。
