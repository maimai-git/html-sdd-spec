# HTML SDD Spec v0.1 Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

Goal：建立一个可复制到其他项目并开源的 HTML SDD v0.1：结构化规范、离线控制台、CLI 校验/渲染/对比、Agent 提示词和资产库示例。

Architecture：使用 sdd.json 作为机器可读事实源，templates/console.html 作为离线阅读器。Python 标准库 CLI 负责初始化、校验、渲染和差异输出。示例数据独立于模板，任何项目都可以替换 JSON。

Tech Stack：Python 3.9+ 标准库、HTML/CSS/JavaScript、JSON Schema、GitHub Actions。

Spec：docs/superpowers/specs/2026-11-10-html-sdd-v01-design.md

## Global Constraints

- 不引入运行时第三方依赖。
- 不修改 sample-asset-service 后端和前端。
- 不执行 DDL，不读取或写入真实密钥。
- HTML 必须离线打开；模板不依赖 CDN。
- 默认中文文案，稳定 ID 使用大写字母、数字和连字符。
- 失败的 check 返回非零退出码；警告不阻断渲染。
- 每个任务完成后运行对应测试和全量测试。

## Review Focus

- 关联 ID 指向不存在记录时，check 必须明确指出来源记录和目标 ID。
- 编码 READY 记录缺少验收、接口实例或 DDL 时，必须阻止通过。
- 敏感值检查不能只看 key 名，也要检查常见 token/password/connection-string 内容。
- render 生成的 JSON 注入不能破坏 HTML/JavaScript。
- diff 对删除记录和字段变更必须给出稳定、可读的结果。

## Risks and Mitigations

| 风险 | 影响 | 处理 |
|---|---|---|
| JSON Schema 和校验器规则重复 | 规则漂移 | Schema 约束结构，checker 负责跨记录语义检查 |
| 模板数据注入破坏脚本 | HTML 无法打开 | JSON 转义、Node 语法检查、渲染测试 |
| 示例过于贴合资产库 | 其他团队不会使用 | 模板完全通用，资产库只放 examples |
| 过早加入在线能力 | 开发成本高、偏离目标 | v0.1 只做本地文件和 CLI |
