# HTML SDD Spec v0.1 设计说明

## 目标

把产品需求、当前代码现状、技术方案、接口、数据表、DDL、上线配置和 Agent 排期放进同一套可追踪格式，减少产品、开发、审核人和 AI 之间的理解偏差。

HTML 是人和 AI 的共同阅读界面；JSON 是机器和 Git 的事实来源。HTML 不读取实时仓库、不执行 DDL，也不替代代码和测试。

## 目标用户

- 产品和项目负责人：快速看目标、范围、进度和阻塞。
- 审核人 Agent：按稳定 ID 拆需求、核对代码现状和提出方案。
- 执行人 Agent：只领取进入“编码 READY”的任务，并回填实现和验证证据。
- 技术同事：查看接口、数据表、架构说明和上线配置。
- 开源使用者：复制模板、编辑 JSON、生成单文件 HTML；有网络时查看 Mermaid 图表，无网络时查看图源回退。

## v0.1 范围

1. sdd.json 数据格式和 JSON Schema。
2. 单文件 HTML 控制台；Mermaid CDN 只作为架构图的可选展示增强。
3. Python 3 标准库 CLI：
   - init：创建最小项目骨架。
   - check：检查稳定 ID、关联关系、必填字段、状态门禁和敏感信息。
   - render：把 JSON 生成 HTML。
   - diff：比较两个版本的需求、任务、接口和数据表变化。
4. 负责人、审核人、执行人 Agent 提示词。
5. 文件资产库真实示例。
6. GitHub Actions、README、贡献规范和许可证占位。

## 不做的事

- 不做在线服务、数据库和多人实时编辑。
- 不自动修改业务代码。
- 不执行 DDL、发布配置或重启服务。
- 不绑定具体模型供应商或 Agent 平台。
- 不把流程、决定、交付强制做成顶级页面；它们作为需求、方案和证据字段保留。

## 页面分类

默认分类固定为：

需求、排期、接口、数据表、架构设计、上线需要配置。

- 排期使用整页表格，不使用左侧目录。
- 其他分类使用左侧分组、右侧单项详情。
- 接口必须展示变更类型、当前现状、请求参数、返回参数、请求实例和响应实例。
- 数据表必须展示新增/变更/复用、表作用和 DDL。
- 技术方案使用文字说明卡片；架构图和时序图支持内联 SVG、图源和文字备用。

## 核心数据结构

~~~text
metadata
baseline
agents[]
requirements[]
plans[]
apis[]
tables[]
architecture[]
configs[]
evidence[]
questions[]
~~~

所有记录有稳定 ID。关联关系只引用 ID，不复制完整内容：

~~~text
REQ-001 -> PLAN-001 -> API-001 -> DATA-001 -> AC-001
~~~

## 状态门禁

推荐状态：

~~~text
待拆分 -> 对齐中 -> 编码 READY -> 开发中 -> 待验证 -> 已验证 -> 已上线
~~~

进入“编码 READY”前必须具备：

- 需求范围和验收标准；
- 当前代码/数据库证据；
- 接口入参、出参和实例；
- 数据表变更类型和 DDL；
- 上线配置；
- 未决问题及影响；
- 负责人、审核人、执行人。

## 证据规则

证据标记区分：

- source：代码、路由、配置文件；
- migration：迁移文件；
- database：已查询的目标数据库；
- runtime：启动、健康检查、接口调用；
- e2e：完整用户链路。

migration 文件不能证明数据库已执行；页面展示不能证明运行成功。

## 安全规则

- HTML 和 JSON 不写 Token、密码、Cookie、私钥、连接串和真实密钥。
- CLI 默认扫描常见敏感字段和高风险字符串。
- 配置只保留键名、非敏感值或占位符。

## 验收标准

- 新用户可以在 3 分钟内根据 README 创建并打开一个 HTML SDD。
- check 能发现坏 ID、孤立关联、缺少接口实例、缺少 DDL 和敏感值。
- render 生成的 HTML 可以单文件打开；无 Mermaid 网络时仍可读取图源/文字回退。
- diff 能说明需求、任务、接口和表的新增、删除、修改。
- 资产库示例可以展示现状、提案、排期和证据链。
- 不要求 Java、Node 或第三方 Python 包。

## 选型理由

保留“接口控制台”式阅读方式，使用 JSON 作为事实源，采用 Python 标准库 CLI。相比在线平台，这个方案安装成本最低、容易放进任意 Git 仓库，也适合先在团队内部验证方法论。
