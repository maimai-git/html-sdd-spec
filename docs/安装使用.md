# HTML SDD Spec 安装与使用

HTML SDD Spec 不连接业务数据库，也不需要单独启动服务。按使用目的选择下面一种方式即可。

本仓库地址是 `git@github.com:maimai-git/html-sdd-spec.git`。正式使用建议固定到版本标签（如 `v0.2.2`），不要直接跟随 `main`。

## 1. 只查看示例（不安装）

需要 Git 和支持原生 gzip 解压的现代浏览器（Chrome、Edge、Firefox 或 Safari）。

```bash
git clone git@github.com:maimai-git/html-sdd-spec.git
cd html-sdd-spec
```

直接打开 `examples/asset-library/index.html`，即可查看真实资产库示例。这个方式不需要 Python 依赖，也不会修改你的业务项目。

## 2. 安装 CLI

建议在虚拟环境中安装：

```bash
python3 --version                 # 需要 Python 3.9+
python3 -m venv .venv
source .venv/bin/activate         # Windows 使用 .venv\\Scripts\\activate
python -m pip install --upgrade pip
python -m pip install "git+https://github.com/maimai-git/html-sdd-spec.git@v0.2.2"
html-sdd --version
```

如果已经把仓库克隆到本地，也可以在仓库目录执行可编辑安装：

```bash
python3 -m pip install -e .
```

CLI 只使用 Python 标准库，没有额外运行时服务。找不到 `html-sdd` 命令时，用下面的等价写法：

```bash
python3 -m html_sdd --version
```

## 3. 在已有项目中建立 SDD

在业务项目根目录执行 CLI，产物会落在约定的 `html-sdd-spec/` 目录：

```bash
cd /path/to/your-project
html-sdd init html-sdd-spec/订单履约
```

然后让 Agent 读取项目代码和规则，使用一句话启动：

```text
用 HTML SDD 实现这个需求：给订单履约增加批量发货能力，结合当前项目代码梳理接口、表、排期和上线配置。
```

生成或更新后检查并渲染页面：

```bash
html-sdd check html-sdd-spec/订单履约/方案事实源.json
html-sdd render html-sdd-spec/订单履约/方案事实源.json \
  --output html-sdd-spec/订单履约/方案对齐.html
open html-sdd-spec/订单履约/方案对齐.html  # macOS；其他系统用浏览器打开
```

`方案事实源.json` 是唯一编辑入口，`方案对齐.html` 是阅读产物。需求、接口、数据表、架构、配置不涉及时可以为空，但要写明“不适用”或“待补充”的原因。架构记录使用 `diagramEngine=mermaid` 时，页面会按需加载固定版本的 Mermaid CDN；网络不可用时仍显示图源和文字回退。

## 4. 作为 Codex Skill 使用

仓库里的 `skills/html-sdd-spec/SKILL.md` 是可直接加载的 Skill 说明。复制到个人 Codex Skill 目录：

```bash
CODEX_SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills/html-sdd-spec"
mkdir -p "$CODEX_SKILL_DIR"
cp skills/html-sdd-spec/SKILL.md "$CODEX_SKILL_DIR/SKILL.md"
```

仓库发布到 GitHub 后，也可以使用 Codex 自带的 `skill-installer`，它会安装到当前账号的 `$CODEX_HOME/skills/html-sdd-spec/`：

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo maimai-git/html-sdd-spec \
  --path skills/html-sdd-spec \
  --ref v0.2.2
```

如果你的 Codex 安装位置不是 `~/.codex`，把命令中的脚本路径换成实际的 `.system/skill-installer/scripts/install-skill-from-github.py`。使用安装器时，目标目录不能已经存在同名 Skill；已有版本先备份或删除后再安装。

重新打开 Codex 或新建对话后，直接说：

```text
用 HTML SDD 先梳理这个项目，不改代码。
```

Skill 默认会先查项目现状，再决定使用单 Agent 还是多 Agent；只有会改变业务规则、接口/表、权限、迁移、外部接入或执行授权的问题才会反问用户。

## 5. 同事协作建议

- 把 `html-sdd-spec/<开发需求目录>/方案事实源.json` 提交到业务项目，作为机器事实源；
- 把 `方案对齐.html` 作为产品、审核人和执行人共同查看的页面；
- CI 中至少执行 `html-sdd check` 和测试；
- 变更前后用 `html-sdd diff before.json after.json --json` 给审核人复核；
- 不把 Token、密码、Cookie、私钥、连接串或真实密钥写入 JSON、HTML、示例或日志；
- DDL、Apollo 和环境变量只在页面中展示，是否执行由项目发布流程负责。

## 按角色读取需求，减少 AI 上下文

先按 ID 获取当前工作摘要；需要接口入参、DDL 或验收标准时，再按对应 ID 展开详情：

```bash
html-sdd context html-sdd-spec/订单履约/方案事实源.json REQ-001 --role owner
html-sdd context html-sdd-spec/订单履约/方案事实源.json REQ-001 --role reviewer --json
html-sdd context html-sdd-spec/订单履约/方案事实源.json REQ-001 --role executor --full
```

`owner` 面向负责人，`reviewer` 面向审核人，`executor` 面向执行人。`--full` 只展开目标记录，关联记录仍保持摘要；继续查询关联 ID 即可获得对应详情。原有 `related` 数据可以直接使用。

升级 CLI 时执行安装命令并追加 `--upgrade`。Skill 也需要更新：手动复制最新版 `SKILL.md`，或先备份旧 Skill 目录后，用安装器安装同一版本标签；更新后重新打开 Codex 对话。

## 6. 常见问题

### 页面打开后没有内容

优先使用当前版本 Chrome、Edge、Firefox 或 Safari。若浏览器限制 `file:` 页面，可在示例目录启动静态服务后访问：

```bash
python3 -m http.server 8766 --directory examples/asset-library
```

然后打开 <http://127.0.0.1:8766/index.html>。

### Skill 没有生效

确认文件位于当前 Codex 使用的 `skills/html-sdd-spec/SKILL.md`，重新打开 Codex 后再以“用 HTML SDD……”开头发起请求。Skill 只负责协作规则，CLI 仍需单独安装。

### `check` 失败

先阅读错误中的稳定 ID 和字段路径。常见原因是状态不在固定枚举中、关联 ID 不存在、`codingReady=true` 但缺少接口/数据/架构/配置证据，或把 migration 文件误写成数据库已执行。
